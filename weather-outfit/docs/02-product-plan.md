# 02. 서비스 기획서 — 우리집 옷날씨 (가칭)

> 날씨 앱을 열면 **우리 가족 한 사람 한 사람의 오늘 옷차림**까지 알려주는 날씨 앱.
> 이름은 가칭입니다. "날씨옷장"은 이미 날씨돌 앱이 기능명으로 쓰고 있어(01-market-research 3.1) 피했습니다. 출시 전 상표 검색(KIPRIS)이 필요합니다.

## 1. 문제와 기회

| 지금의 날씨 앱 | 사용자가 실제로 하는 일 |
|---|---|
| 기온·강수·미세먼지 **숫자**를 보여줌 | 숫자를 보고 "그래서 뭘 입지?"를 **직접 판단** |
| 한 사람 기준 | 아침마다 **아이·부모님 옷까지** 챙김 |
| 체감은 사람마다 다른데 같은 정보 | 추위 타는 엄마, 더위 타는 아이는 **다르게** 입어야 함 |

조사 결과(01 문서 4장), **가족 구성원별 프로필 + 나이·건강·민감도 보정 + 공식 데이터 + 쇼핑 연결**을 함께 하는 서비스는 국내외에서 확인되지 않았습니다. 옷차림 추천 앱은 모두 1인 기준이거나 영유아 1명 대상입니다.

## 2. 타깃

- **1차**: 미취학·초등 자녀를 둔 30~40대 부모 (매일 아침 등원 옷 고민)
- **2차**: 고령 부모님을 챙기는 자녀 (한파·폭염·미세먼지 건강 이슈)
- **3차**: 본인 출근 코디가 필요한 직장인

## 3. 핵심 가치 제안

1. **한 화면에 가족 전체 코디** — "지은: 자켓 / 엄마: 코트+목도리 / 서준: 트렌치+마스크 / 하린: 내복+바디슈트"
2. **개인 체감온도** — 같은 12℃여도 사람마다 다르게 계산하고, **왜 이렇게 추천했는지** 근거를 보여줌
3. **공식 데이터** — 기상청 단기예보·생활기상지수, 에어코리아 실측값 (출처 표기)
4. **챙길 것 체크** — 우산, 마스크, 선크림, 목도리를 가족별로 정리
5. **(확장) 부족한 아이템 → 쇼핑** — 추천 아이템마다 표준 카테고리 키(`outer.padding`, `kids.bodysuit` 등)가 붙어 있어 커머스와 바로 연결 가능

## 4. MVP 범위 (이번 구현)

| 영역 | 기능 | 상태 |
|---|---|---|
| 로그인 | 카카오·네이버·구글 소셜 로그인, 둘러보기(게스트), 로그아웃, 회원 탈퇴 | ✅ 구현 |
| 날씨 | 현재 기온·체감·최저/최고·일교차, 시간별(등원·하원·퇴근 표시), 미세먼지/초미세먼지/자외선/강수확률 | ✅ 구현 |
| 데이터 | 기상청 초단기실황 + 단기예보, 생활기상지수(자외선), 에어코리아 근접측정소 실측, 카카오 좌표→행정구역 | ✅ 구현 (키 없으면 데모 데이터) |
| 가족 | 구성원 추가/수정/삭제: 이름·관계·출생연도·추위/더위 민감도·활동량·(동의 시) 건강 상태·체온 | ✅ 구현 (기기 저장) |
| 추천 | 구성원별 개인 체감온도 → 옷 두께 5단계 + 겉옷/상의/하의/신발/소품 + 주의사항 + 추천 근거 | ✅ 구현 |
| 개인정보 | 건강정보 별도 동의, 동의 철회 시 즉시 삭제, 건강정보 서버 미전송 | ✅ 구현 |
| 쇼핑 | "추천 아이템 둘러보기" 자리만 마련 | ⏳ 다음 단계 |

## 5. 화면 구성 (IA)

```
로그인 ─┬─ 카카오 / 네이버 / Google
        └─ 로그인 없이 둘러보기
탭 ─┬─ 오늘   : 인사 → 날씨 히어로 카드 → 지표 4종 → 시간별 → 가족 코디 카드 목록
    │           └─ 구성원 상세: 개인 체감온도, 두께 미터, 주의할 점, 부위별 코디, 추천 근거, 쇼핑(예정)
    ├─ 가족   : 구성원 목록 → 추가/수정 (모달)
    └─ 설정   : 계정(로그아웃/탈퇴), 건강정보 동의 토글, 데이터 출처
```

경쟁 앱 UI 패턴 중 가져온 것(01 문서 1.3, 2장): 상단 한 줄 요약 + 그라디언트 히어로(Apple 날씨), 가로 시간별 스트립(공통), 카드형 지표(케이웨더), 일과 시간 마커(차별화).

## 6. 추천 로직

`packages/core/src/recommend.ts` — 규칙 기반이라 근거를 그대로 사용자에게 보여줍니다.

1. **체감온도** (기상청 산출식): 10℃ 이하·풍속 1.3m/s 이상은 바람냉각, 24℃ 이상은 습구온도 기반 여름철 체감온도
2. **개인 보정** (합계 −6 ~ +5℃로 제한)

   | 요인 | 보정 |
   |---|---|
   | 영아(<2세) / 유아(2~6세) | −3 / −1.5 ("어른보다 한 겹 더") |
   | 65~74세 / 75세 이상 | −2 / −3 |
   | 추위·더위 민감도 −2…+2 | ×2℃ (−4…+4) |
   | 회복 중 / 미열(≥37.5℃) | −2 / −2 |
   | 임신 중 | +1.5 |
   | 수족냉증 (15℃ 미만일 때) | −1 |
   | 야외 활동 많음 (15℃ 미만) / 주로 실내 | −1.5 / +1 |

3. **기온별 옷차림 8단계** (28↑ / 23–27 / 20–22 / 17–19 / 12–16 / 9–11 / 5–8 / 4↓) → 두께 1~5
4. **연령별 아이템 치환**: 영아는 바디슈트·우주복·덧신, 아동은 내복·장화·아쿠아슈즈
5. **환경 보정**
   - 일교차 ≥10℃: 겉옷 챙기기
   - 강수확률 ≥60% 또는 강수: 우산 + 방수 신발(아이는 장화), 눈이면 미끄럼 방지. 30~59%: 접이식 우산
   - 자외선 ≥3: 선크림, ≥6: 모자·선글라스. 6개월 미만 영아는 선크림 대신 그늘·모자
   - 미세먼지: 나쁨 이상이면 마스크. **호흡기 질환·노약자·임신부는 한 단계 낮은 기준(민감군)**. **24개월 미만은 마스크 대신 외출 줄이기** (질식 위험)
   - 바람 ≥9m/s: 바람막이, ≥14m/s 경고
   - 폭염(체감 33℃↑, 민감군 31℃↑), 한파(−12℃↓, 민감군 −5℃↓) 경고. 심혈관 질환은 아침 외출 주의
   - 체온 ≥38℃: 휴식 권고를 최상단에

### 향후 고도화
- **피드백 학습**: 저녁에 "오늘 추웠어요/딱 좋았어요/더웠어요"를 받아 개인 보정값 자동 조정
- **시간대별 코디**: 등원(8시)·하원(16시) 기온으로 각각 계산
- **내 옷장 등록**: 가진 옷에서 추천, 없는 카테고리는 쇼핑 추천

## 7. 건강앱 연동 방침

| 단계 | 방식 |
|---|---|
| MVP (지금) | 추위/더위 민감도 직접 선택 + (동의 시) 질환·체온 수동 입력, **기기에만 저장** |
| v1.1 | Apple HealthKit `bodyTemperature`, Android Health Connect `BodyTemperatureRecord` 읽기 (개발 빌드 필요). 실제로 체온 데이터가 있는 사용자는 적어 선택 기능으로 둠 |
| v1.2 | 웨어러블 피부온도·수면 데이터로 컨디션 보정 (검토) |

법적 요건(01 문서 6.3): 건강정보는 민감정보라 **별도 동의**가 필요하고, **14세 미만 자녀 정보는 법정대리인 동의**가 필요합니다. 부모가 자녀 프로필을 만들기 때문에 가입 시 법정대리인 동의 문구를 넣어야 합니다. 법률 검토는 필수입니다.

## 8. 수익화 로드맵

| 단계 | 모델 | 내용 |
|---|---|---|
| 0. 무료 (지금) | — | 소셜 로그인, 가족 4~5명, 광고 없음으로 사용자 확보 |
| 1. 커머스 연결 | 제휴 수수료 | 추천 카테고리 키 → 무신사·지그재그·쿠팡·네이버쇼핑 등 제휴 링크. "우리 아이 장화 없나요?" |
| 2. 프리미엄 | 구독 | 가족 6명 이상, 피드백 학습, 시간대별 코디, 위젯, 알림 (CARROT 가족 요금제 참고) |
| 3. 데이터·광고 | B2B | 날씨×의류 수요 인사이트(비식별 통계), 날씨 트리거 광고 |

쇼핑 확장 설계: `OutfitItem.category`가 이미 표준 키라서, 서버에 `category → 상품 검색 쿼리/제휴 딥링크` 매핑 테이블 하나만 추가하면 됩니다. 아이·성인 사이즈는 가족 프로필의 나이로 필터링합니다.

## 9. 성공 지표 (MVP)

- D1/D7 리텐션 (아침 날씨 확인 습관) · 가족 구성원 평균 등록 수 (목표 ≥2.5)
